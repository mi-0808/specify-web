# Specify 企画書：部屋のレシピ

> **SNSで見た理想の部屋を、今買える家具の「レシピ」にする。**

Specify（＝特定する）は、理想の部屋の雰囲気から、それを再現するために「何を・どこで・いくらで」買えばいいかを特定するアプリ。

旧企画（写真を送って収納提案・現場診断を受け取る）は終了し、この企画に置き換える。
作り方は [MVP 設計書](specify-recipe-mvp.md) にまとめている。

---

## 0. ターゲット

**引っ越したばかりの、一人暮らしの20代。**

ここから、レシピの前提条件を次のように置く。✅は確定、🔍はインタビューで確かめる仮説。

| 前提 | 内容 | レシピへの影響 |
|---|---|---|
| ✅ 部屋が狭い | 1K・ワンルーム、6〜8畳ほど | 小さい部屋で成り立つ組み合わせにする。大型家具は控えめに |
| ✅ 賃貸 | 退去時に元に戻す必要がある | 壁に穴を開けない、床を傷つけない商品だけを載せる |
| ✅ 引っ越し直後でお金に余裕がない | 初期費用を払った直後 | 安く揃う店を中心にし、「最初の1点」だけでも雰囲気が変わる順番を示す |
| 🔍 予算帯 | 3万円・5万円・10万円 | この3段階でレシピを作る |
| 🔍 最初に用意する雰囲気 | 韓国風・北欧ナチュラル・カフェ風 | この3つから始める |
| 🔍 扱う店 | ニトリ・IKEA・無印・3COINS | 小物は3COINSで安く揃える |
| 🔍 家具がどこまで揃っているか | ベッドと収納くらいはある | レシピは「雰囲気を作る物」（ラグ・照明・カーテン・小物）を中心にする |

---

## 1. 課題

> SNSで見た理想の部屋を、自分の予算で、どこで何を買えば再現できるのかが分からない。だから行動に移せない。

ユーザーがつまずいている壁は3つ。

| 壁 | ユーザーの疑問 |
|---|---|
| ① 特定 | 「この家具、何ていう商品？」 |
| ② 入手先 | 「どこで売ってるの？」 |
| ③ 価格 | 「高いんじゃない？部屋全体で全部でいくら？」 |

### 今ある手段と、まだ埋まっていないところ

| 今ある手段 | できること | できないこと |
|---|---|---|
| Googleレンズ・Pinterestの画像検索 | 家具を1点ずつ探す | 似た別物や海外のショップが混ざる。部屋全体の総額は出ない |
| RoomClipなどのインテリアSNS | 投稿者がタグを付けた商品は分かる | 高い品や販売終了品も多い。予算に合わせた代わりの品は出ない |
| ChatGPT | 雰囲気を言葉にする、方向性を出す | 実在する商品か、今の値段かが不確か |

まだ誰も埋めていないのは、**「部屋全体を、自分の予算で、今買える実物で」**の部分。ここを Specify が埋める。

---

## 2. 解決手法：部屋のレシピ

雰囲気ごと（北欧、韓国風、カフェ風など）に、実際に売っている商品を、予算別に組み合わせた一覧。

### 1つのレシピに載せるもの

| 項目 | 内容 |
|---|---|
| 雰囲気 | 北欧、韓国風など。見本の写真を付ける |
| 予算帯 | 例：3万円・5万円・10万円 |
| 商品の一覧 | 部屋の中での役割（ラグ・照明・カーテンなど）、商品名、店（ニトリ・IKEA・無印など）、価格、商品ページへのリンク、価格を確認した日 |
| 総額 | 一覧の合計金額 |
| 買う順番 | 「最初にこれを買うと雰囲気が一番変わる」という優先順位 |

### ChatGPT などとの違い

レシピの商品は人が選んで確認するので、**実在していて、今買えて、値段が正しい**ことを保証できる。ここを守れないなら作る意味がない。

---

## 3. フロー

1. **理想を引き出す**：雰囲気の写真を選び、予算を入力してもらう
2. **レシピを出す**：雰囲気と予算に合ったレシピを表示する
3. **記録する**：買った家具が届いたら、部屋にどう置いたかを記録する
4. **次の一手を出す**：記録をもとに、次に何を足せば・変えれば理想に近づくかを出し続ける

---

## 4. 必要なページ（案）

| ページ | 役割 |
|---|---|
| トップ | 何ができるアプリか伝え、始めてもらう |
| 理想を引き出す | 雰囲気の写真を選ぶ、予算を入力する |
| レシピ | 商品一覧、総額、買う順番 |
| 記録 | 届いた家具を登録する |
| ホーム | 今の部屋の状態と、次の一手 |
| ログイン | 記録を残すため |

---

## 5. 方針

- **API は原則使わない。** レシピは人が作る。必要になったときだけ追加を検討する。
- **ランキング機能は単独では作らない。** 各店の公式サイトにすでにあるため。レシピの中で「この雰囲気で人気の品」として扱う。
- 見た目と操作は [デザイン規約](design-guidelines.md) に従う。

### やらないこと

- ChatGPT など、既存のアプリで代わりがきく機能を主機能にすること
- 新しい解決策として十分に役立つとは言えない、中途半端な機能の開発
- 必要のないソーシャル機能（発信・共有）

### 運用の負担（承知のうえで進める）

- レシピの商品を選ぶ作業
- 価格と在庫の定期的な確認（確認した日をレシピに残し、古くなったものから見直す）

## 7. インタビューで確かめること

- 3つの壁（特定・入手先・価格）のうち、いちばん大きいのはどれか
- 1部屋にかけてもいい予算はいくらか（3万・5万・10万の段階で合っているか）
- 引っ越した時点で、家具はどこまで揃っているか
- 憧れている雰囲気はどれか（韓国風・北欧ナチュラル・カフェ風で足りるか）
- 実際に買わなかったときの最後の理由は何か（「サイズが合うか不安」「組み合わせて失敗するのが怖い」など、別の壁がないか）
- レシピを見たら、実際に1点目を買うか
