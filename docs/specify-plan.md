# Specify 企画書：部屋を見つけて、そのまま買う

> **ネットで見たおしゃれな部屋から、家具を特定して、自分に合った買い方で手に入れる。**

Spotify が「曲を探して、その場で聴ける」ように、Specify は「部屋を探して、その場で家具の手に入れ方まで分かる」体験をつくる。
Specify（＝特定する）の名前どおり、部屋の中の家具を特定するところが中心になる。

### これまでの経緯

| 時期 | 企画 | 結果 |
|---|---|---|
| 〜2026-10 | 写真を送って、収納提案・現場診断を受け取る | 終了・削除済み |
| 2026-10-15 | 部屋のレシピ（雰囲気×予算ごとに、人が商品を選んで組む） | MVP を作ったが、手作業では分かれ道が増えるほど追いつかないため終了・削除済み（git の履歴には残っている） |
| 2026-10-16〜 | **検索＋買い物体験**（この企画書） | 計画中 |

---

## 0. ターゲット

**引っ越したばかりの、一人暮らしの20代。**（前の企画から変えない）

| 前提 | 影響 |
|---|---|
| 1K・ワンルーム、6〜8畳 | 小さい部屋で使える家具を優先して出す |
| 賃貸 | 壁に穴を開けない商品を優先する |
| お金にも時間にも余裕がない | 「安く似せる」「組み立てが楽」「中古でもらう」などの手に入れ方が特に効く |

---

## 1. 課題

> SNSや動画でいい雰囲気の部屋を見ても、その家具が何で、どこで、いくらで、どうやって手に入るのかが分からない。だから行動に移せない。

| 壁 | ユーザーの疑問 |
|---|---|
| ① 特定 | 「この家具、何ていう商品？」 |
| ② 入手先 | 「どこで売ってるの？」 |
| ③ 価格 | 「高いんじゃない？」 |
| ④ 手に入れ方 | 「もっと安い似たものはない？」「組み立ては大変？」「中古やもらえるものはない？」 |

---

## 2. 体験の流れ

| 段階 | 内容 |
|---|---|
| 1. 見つける | YouTuber のルームツアー、インスタのリールなど、ネットにあるおしゃれな部屋を、アプリの中で見られる |
| 2. 特定する | 部屋に映っている家具を自動で特定し、複数の店の候補を一度に並べる |
| 3. 比べて選ぶ | 家具ごとに、手に入れ方を比べて選べる（下の表） |
| 4. 中で買う | 選んだ手に入れ方で、そのまま買う |

### 比べる軸

| 軸 | 選択肢の例 |
|---|---|
| 値段とデザイン | 安く似せる（ニトリ・3COINS など）／高くてもデザインで選ぶ（本物） |
| 組み立ての手間 | 完成品／組み立てが簡単／難しい／組み立てサービスあり（IKEA・ニトリには有料のサービスがある） |
| 新品か中古か | 新品／中古で安く買う／地元で無料・格安で譲ってもらう（ジモティーなど） |
| 届き方 | 届くまでの日数、送料、店で受け取る、自分で運ぶ |

---

## 3. 既存サービスとの違い

| サービス | できること | Specify との違い |
|---|---|---|
| RoomClip | 投稿された部屋写真から、写っている商品を買える（月600万人） | 投稿されたものだけ。手に入れ方の比較はない |
| 楽天ROOM | ユーザーが商品を集めて紹介する | 楽天の商品だけ。部屋から探す形ではない |
| Google レンズ | 写真から似た商品を探す | 1枚ずつで、たくさん比べたり集めたりはしにくい |
| IKEA Kreativ など | 自分の部屋で家具を試す | 自社の商品だけ |

**Specify にしかないもの：ネット上の部屋を横断して探せて、家具ごとに「どう手に入れるか」まで比べて選べること。**

---

## 4. 実現の壁と、現実的な方法

| 部分 | 壁 | 現実的な方法 |
|---|---|---|
| 動画を集めて表示する | 他人の動画・写真を保存して載せると著作権の侵害。インスタは規約で自動取得を禁止 | 公式の埋め込み機能を使う。クリエイターと提携し、紹介料を分ける |
| 商品を自動で特定する | 画像検索では「似た商品」しか出ず、同じものとは限らない | AI で候補を出し、確からしさを表示する。最初は人が確認する |
| 商品データを集める | ニトリ・IKEA・無印には公開 API がなく、自動取得は規約で禁止されがち | 楽天・Amazon のアフィリエイト API など、正式に使えるデータから始める |
| 組み立ての手間 | 店ごとに書き方がばらばらで、比べられる形の情報がない | 「組立品／完成品」や組み立て時間を集めて、自分たちで段階をつける |
| 中古・地元 | メルカリ・ジモティーには公開 API がない。1点ものですぐなくなる | 最初は検索結果ページへのリンクにとどめる |
| 中で買う | アプリ内で決済まで完結させるには各店との提携が必要 | 最初はアフィリエイトのリンクで店に送る |

Spotify がレコード会社と契約して曲を流しているように、Specify も **クリエイター（部屋の動画）と店（商品）との関係づくり** が事業の中心になる。

---

## 5. 方針

- **API は必要なものを使う。** 前の企画の「API は原則使わない」は、この企画では成り立たないためやめる。ただし、使うのは規約上正式に使えるもの（公式の埋め込み、アフィリエイト API など）に限る。
- 見た目と操作は [デザイン規約](design-guidelines.md) に従う。

### やらないこと

- ChatGPT など、既存のアプリで代わりがきく機能を主機能にすること
- 新しい解決策として十分に役立つとは言えない、中途半端な機能の開発
- 必要のないソーシャル機能（発信・共有）
- 他人の動画・写真を、許可なく保存・転載すること

---

## 6. 作る順番

MVP（小さな検証）は作らず、本番の機能として順に作る。設計は [設計書](specify-design.md)。

| 段階 | 作るもの | 状況 |
|---|---|---|
| 1 | **眺めて見つける**：ネット上のルームツアー動画を自動で集め、おすすめの部屋を眺めて探せる。部屋ごとに、動画の説明欄で紹介されている家具と、その購入先を出す | 実装中 |
| 2 | **手に入れ方を比べる**：家具ごとに、安い版・中古・組み立ての手間などを比べて選べる | 未着手 |
| 3 | **中で買う**：見つけてから買うまでを、アプリの中で一続きにする | 未着手 |

いちばん大事にするのは **「部屋を探す体験」**。ユーザーが最初にするのは、検索ではなく、おすすめの部屋を眺めて見つけること。
