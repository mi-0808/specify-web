# Specify 設計書：眺めて見つける（段階1）

[企画書](specify-plan.md) 6章の段階1を、本番の機能として作るための設計。
見た目と操作は [デザイン規約](design-guidelines.md) に従う。

---

## 1. 作るもの

> **みんなが見つけたルームツアー動画を、ジャンルごとに眺めて見つけられる。部屋ごとに、紹介されている家具と購入先が分かる。**

| 機能 | 内容 |
|---|---|
| 部屋の追加 | ログインした人（運営も同じ）が `/add` に YouTube の動画リンクを貼り、ジャンルを1つ決めて入れる。説明欄の「使用アイテム」を読み取って保存する |
| 毎日の取り直し | 1日1回、YouTube の公式 API で保存済みの動画を取り直す（規約のため） |
| 眺める | トップに、集めた部屋をカードで並べる。ジャンルで絞り込める |
| 部屋の詳細 | 動画（公式の埋め込み）と、紹介されている家具の写真・商品名・購入先 |

見るのはログイン不要。部屋の保存と、動画リンクからの部屋の追加は、ログインした人だけ。手に入れ方の比較・アプリ内の購入は、段階2以降。

## 2. 画面と URL

| パス | 画面 |
|---|---|
| `/` | 眺める：部屋のカードの一覧（新しい順、24件ずつ）。`?genre=<ID>` でジャンル絞り込み、`?page=2` で続き |
| `/rooms/[id]` | 部屋の詳細（`id` は YouTube の動画 ID） |
| `/saved` | 保存した部屋（ログイン必要。スマホは下のタブ「保存」、パソコンは右上の「保存した部屋」から） |
| `/me` | マイページ（未ログインなら会員登録・ログインの案内。ログイン中はメールアドレス、自分が作ったジャンル（部屋の数。押すとそのジャンルの一覧、ゴミ箱で確かめてから消す。0個なら出さない）、自分が探索した部屋、ログアウト） |
| `/add` | 気になる動画の部屋を探索（ログイン必要。一覧の最後に置く「気になる動画の部屋を探索」のカードから開く。部屋が0件のときもこのカードを出す。ジャンルで絞り込んでいるときは `?genre=<ID>` 付きで開く。貼った動画は「自分が探索した部屋」に残る） |
| `/api/cron/collect` | 毎日の取り直し（Vercel Cron から1日1回呼ぶ。`CRON_SECRET` がないと動かない） |
| `/login` | ログイン・新規登録（`?signup=1` で新規登録から開く。移動先の `next` はこのサイトの中のパスだけ） |

### ヘッダー

- スマホ：上のヘッダーは出さず、下にすりガラスのタブバー（さがす・保存・マイページ）。ページの先頭は大きな見出し（デザイン規約 5.5）。
- パソコン：右上にリンクを横一列で並べる。未ログインは「さがす／ログイン／新規登録」、ログイン中は「さがす／保存した部屋／マイページ」（ログアウトはマイページの中）。
- 「部屋を探索」はヘッダーに出さず、一覧の最後のカードから開く。
- 「さがす」の先頭には、ログイン中で保存した部屋があれば「また見る」（保存した部屋を新しい順に10件、横にスクロール）を出す。

### `/` 眺める

- 上に短いコピーと、ジャンルの列（公式の8つ → ユーザーのジャンル）。押すと絞り込み、もう一度押すと解除。
- 部屋のカード：サムネイル、タイトル、チャンネル名、家具の数。カード全体が `/rooms/[id]` へのリンク。
- 部屋がまだないとき：「まだ部屋がありません。気になる動画のリンクを貼って、最初の部屋を入れてください。」ジャンルで絞り込んでいるときは「「○○」の部屋はまだありません。」

### `/rooms/[id]` 部屋の詳細

- 動画：`youtube-nocookie.com` の公式の埋め込み。下にチャンネル名（チャンネルへのリンク）と「YouTube で見る」。
- 家具：説明欄で紹介されている順に並べる。写真・商品名（取れなかったときは説明欄のラベル）・ラベル・店の名前・「購入先を見る ↗」（新しいタブ）。
- 注意書き：「動画の説明欄で紹介されているアイテムです。リンク先は、クリエイターが紹介しているページです。」
- 保存ボタン：動画のリンクの行の右側に、しおりのアイコン＋「保存」。ログイン中は押すと保存され、アイコンが塗られて「保存済み」になる。未ログインで押すと、会員登録へ案内する吹き出し（新規登録・ログインのリンク付き。外側のクリックか Esc で閉じる）を出す。

### ジャンル

- 1つの部屋は、1つのジャンルにだけ入る。ジャンルは、部屋を `/add` で最初に入れた人が決め、あとから変えられない。
- 公式ジャンル：韓国・北欧・ナチュラル・カフェ・モノトーン・ホテルライク・アンティーク・ミニマル（`created_by` が空）。誰も消せず、その部屋も誰も消せない（変な部屋は運営が DB から消す）。
- 一覧のジャンルの列：公式の8つを決まった順に並べ、そのあとにユーザーが作ったジャンルを部屋の多い順に並べ、最後に点線の丸「＋」を置く。部屋が0のジャンルも出す。
- 「＋」：標準の `<dialog>` で中央に開く。ログイン中はジャンル名（12文字まで・同じ名前は不可）を入れて作る。未ログインなら会員登録へ案内する。作ると、そのジャンルの空の一覧を開く。
- 部屋を消す：部屋の詳細で、部屋が入っているジャンルを作った本人にだけ「この部屋を消す」を出す。確かめてから消す（保存も消える）。
- ジャンルを消す：作った本人がマイページから。入っていた部屋は消えず「ジャンルなし」になり、「すべて」にだけ残る。ジャンルなしの部屋は、だれかが `/add` で貼ると、そのジャンルに入る。
- 荒らし対策：12文字まで、同じ名前は不可、リンクは入れられない。通報の仕組みは利用者が増えてから足す。

### `/add` 動画から部屋を追加

- YouTube の動画リンク（`watch?v=`・`youtu.be`・`shorts`・`live`）を貼る。すでにある部屋なら、その部屋へ移動する（ジャンルは変わらない）。
- 入れるジャンル：ジャンルの一覧から開いたときは、そのジャンルに入れる（「「○○」に入れます」と出し、選ぶ欄は出さない）。「すべて」から開いたときは、プルダウンで選ぶか「＋ 新しいジャンルを作る」で名前を入れて作る。新しいジャンルは、動画が使えると分かってから作る。
- 取り込んだ部屋は、みんなのフィードにも並ぶ。次のときは追加せず、理由を出す。
  - 家具・インテリアの動画ではない（タイトルと説明欄に「ルームツアー」「部屋」「インテリア」「家具」「◯畳」「1K」などの言葉がない）→「家具やインテリアの動画ではないため、これは使えません。」
  - 説明欄に、買える家具が3つ以上ない
  - 動画が見つからない・ほかのサイトでの再生が許可されていない
- 商品ページを順にたどるので、30秒〜1分ほどかかる（`maxDuration = 120`）。

## 3. 部屋の取り込みと、毎日の取り直し

```
/add（ログインした人）
  → YouTube videos.list：貼られた動画の情報を取る
  → 説明欄から「ラベル＋URL」を読み取る（4章）
  → URL を買い物サイトの許可リストで確認し、商品ページの名前と写真（og:title・og:image）を取る（5章）
  → 買える家具が3つ以上ある動画だけ、rooms（ジャンルつき）と room_items に保存する

Vercel Cron（1日1回、日本時間 3:00）
  → GET /api/cron/collect（Authorization: Bearer CRON_SECRET を確認）
  → YouTube videos.list：保存済みの全動画の情報を取り直す
  → 説明欄が変わった動画は、家具を読み直す（条件を満たさなくなったら削除）
  → 取り直しで消えていた・埋め込み不可になった動画は削除する
```

- 決まった検索語で YouTube を探す自動収集はやめた（毎日同じ検索結果が返り、部屋が増えなかったため）。
- API の使用量：videos.list は50件ごとに1ユニット（1日の上限は10,000）。
- 説明欄が前回と同じ動画は、家具の読み取りと商品ページの取得をやり直さない（`description_hash` で判定）。
- 動画は4本ずつ並行して処理する（商品ページは1本あたり4件ずつ、同時に最大16件）。1回の実行は240秒で打ち切り、残りは次回に回す。

### あとで作るもの：毎晩の候補探し

部屋が足りなくなったら、毎晩 YouTube から候補を探す。決まっていること：
- 対象：作って7日以内のジャンル → 部屋が10未満のジャンル → 最近よく保存されるジャンルの順。
- 検索語：ジャンル名と、保存された動画の説明欄のハッシュタグ。新しい順・前回以降に公開された動画に絞る（search.list は1回100ユニット）。
- 入れるのは1日5本まで。候補は多めに出し、運営が `/add` と同じ経路で入れる。

### YouTube API の規約に合わせること

- 動画は公式の埋め込みで表示し、YouTube の動画・チャンネルへのリンクを付ける。
- API で取ったデータは、毎日の取り直しで最新に保つ（30日以上古いままにしない）。消えた動画は削除する。

## 4. 説明欄の読み取り

次の書き方を「ラベル＋URL」として読み取る。

| 書き方 | 例 |
|---|---|
| 同じ行 | `デスク：https://…`、`デスク: https://…` |
| 次の行に URL | `デスク` の次の行に `https://…` |
| 時刻付き | `13:15 ランプ` の次の行に `https://…`（時刻は外す） |

次は読み取らない。

- URL のない行（「楽天roomに載せています」など）
- 見出し（`●` で始まる行）や、「まとめ」「こちら」「チャンネル登録」「BGM」などを含むラベル
- 買い物サイトの許可リストにない URL（SNS・メール・音楽など）
- 楽天ROOM の「人のおすすめ一覧」のページ（`/ユーザー名` や `/ユーザー名/items`）。`/ユーザー名/数字` の商品ページだけを使う
- 「Amazon」「楽天」のような店名だけのラベルで、商品名も取れなかったもの（何の家具か分からないため）

## 5. 商品ページの取得（安全のための制限）

説明欄の URL は誰でも書けるので、サーバーから取りに行く先を制限する（SSRF 対策）。

- `https://` だけ。リダイレクトは自分でたどり、**1回ごとに行き先が許可リストにあるか**を確認する（最大5回）。
- 許可リスト（`src/lib/collector/shops.ts`）：楽天（短縮 URL `a.r10.to`・アフィリエイトの転送先・`item.rakuten.co.jp`・`room.rakuten.co.jp`）、Amazon（`amzn.to`・`amzn.asia`・`www.amazon.co.jp`）、ニトリ、IKEA、無印良品、3COINS（PAL CLOSET）、ZOZOTOWN。
- 1回の取得は15秒で打ち切る（楽天の商品ページは応答まで約10秒かかることがある）。ロボットからの接続を拒否する店（ニトリなど）は、拒否を回り道せず、ラベルと店の名前だけで出す。読むのは HTML の先頭 512KB まで。
- 取れなかったときは、説明欄のラベルと店の名前だけで表示する。Amazon はロボットに汎用ページしか返さないので、今は商品名・写真が取れない（段階2で、Amazon のアフィリエイト API を使って取る）。
- 楽天の商品名は、先頭の宣伝（【ポイント5倍】＼激安！／[セール…] など）と末尾のショップ名を外して保存する。
- 商品写真は店が共有用に出している画像（og:image）を、そのまま表示する（こちらには保存しない）。
- Amazon のリンクは、最初にたどり着いた Amazon のページから商品番号（ASIN）を取り、`https://www.amazon.co.jp/dp/{ASIN}?tag={AMAZON_ASSOCIATE_TAG}` に替えて保存する。クリエイターのタグは外す。商品ページ以外（検索など）は、行き先はそのままでタグだけ替える。`AMAZON_ASSOCIATE_TAG` が空なら説明欄のリンクのまま。楽天などは説明欄のリンクのまま。

## 6. データ

```sql
rooms(
  id text primary key,          -- YouTube の動画 ID
  title text, channel_id text, channel_title text,
  thumbnail_url text, published_at timestamptz,
  genre_id uuid references genres on delete set null,   -- 1部屋1ジャンル。ジャンルが消されたら空
  description_hash text, refreshed_at timestamptz
)
room_items(
  room_id text references rooms on delete cascade,
  position int,                 -- 説明欄での順番
  label text,                   -- 説明欄のラベル（「デスク」）
  url text,                     -- 家具のリンク（Amazon は Specify のタグ付き、ほかはクリエイターのリンクのまま。5章）
  shop_host text,               -- 最後にたどり着いた店のホスト
  product_title text, image_url text,   -- 商品ページから取れたもの（なければ null）
  primary key (room_id, position)
)
```

- RLS：誰でも読める。入れる・更新するのは収集処理と `/add` だけ（サービスロールのキー）。消すのは、部屋が入っているジャンルを作った本人だけ。
- `saved_rooms(user_id, room_id, created_at)`：本人だけが読み書きできる。部屋が消えたら保存も消える。
- `explored_rooms(user_id, room_id, explored_at)`：`/add` で動画を貼った履歴（すでにある部屋でも残す）。本人だけが読み書きできる。
- `genres(id, name, created_by)`：誰でも読める。作るのはログインした人。`created_by` が空なら公式ジャンル。消せるのは作った本人だけ（RLS で守る）。
- 関数：`genres_with_counts()`（部屋の数つき一覧。公式が先、そのあとユーザーのジャンルを部屋の多い順）。
- 旧企画の `saved_recipes`・`purchases` は残したまま（企画書 7章）。

### 環境変数

| 名前 | 用途 |
|---|---|
| `YOUTUBE_API_KEY` | YouTube Data API v3 のキー（Google Cloud で発行） |
| `SUPABASE_SERVICE_ROLE_KEY` | 収集処理の書き込み用（サーバー専用） |
| `CRON_SECRET` | `/api/cron/collect` を守る。Vercel Cron が自動で `Authorization` ヘッダーに付ける |
