# デザイン規約

再企画後の Specify で守る、見た目と操作の決まりごと。
タイポグラフィ・ボタン・モーダルは Apple の Human Interface Guidelines（HIG）、配色は Material Design 3（M3）の考え方をもとに、Web 向けに置き換えている。

- 新しく作るページはこの規約に従う。既存ページは作り直すときに合わせる。
- 規約から外れる場合は、理由を PR に書く。

---

## 1. 共通原則

| 原則 | 内容 |
|---|---|
| 1画面1目的 | 1画面でユーザーにしてほしいことは1つ。主ボタンも1つ |
| 状態を必ず見せる | 読み込み中・送信中・完了・失敗のどれなのかを常に画面に出す |
| 失敗したら直し方まで書く | 「何が起きたか」と「どうすれば直るか」を1〜2文で書く |
| 色だけに頼らない | エラーや選択状態は、色に加えてアイコンや文言でも伝える |
| 用語をそろえる | 同じものは全画面で同じ呼び方にする（例：「提案」「記録」） |

---

## 2. タイポグラフィ

### 書体

システムフォントを使う（HIG：プラットフォーム標準の書体を優先）。Web フォントは読み込まない。

```css
font-family: system-ui, -apple-system, "Hiragino Sans", "Hiragino Kaku Gothic ProN", "Noto Sans JP", sans-serif;
```

### 文字サイズの段階

HIG の Text Style（iOS 標準サイズ）を、そのまま px に置き換える。iOS の Safari では 1px が 1pt に当たるので、数字は変えていない。
行送りだけは日本語用に広げている（HIG の値は欧文向けで、日本語には狭い）。

| 用途 | HIG 名 | サイズ | 太さ | 行送り |
|---|---|---|---|---|
| 画面タイトル（トップの大見出し） | Large Title | 34px | 700 | 1.4 |
| ページ見出し | Title 1 | 28px | 700 | 1.4 |
| セクション見出し | Title 2 | 22px | 700 | 1.4 |
| 小見出し | Title 3 | 20px | 600 | 1.5 |
| カード見出し・強調 | Headline | 17px | 600 | 1.6 |
| 本文 | Body | 17px | 400 | 1.7 |
| 補足文 | Callout | 16px | 400 | 1.7 |
| 説明・ラベル | Subheadline | 15px | 400 | 1.6 |
| 注記 | Footnote | 13px | 400 | 1.6 |
| キャプション | Caption 1 | 12px | 400 | 1.5 |

### 守ること

- **12px 未満は使わない。** HIG の下限は 11pt だが、日本語は画数が多く 11px では読みにくいため。
- **入力欄の文字は 16px 以上。** 16px 未満だと iOS の Safari が入力時に画面を勝手に拡大する。
- **単位は rem で指定する。** px で固定すると、ブラウザの文字サイズ設定（HIG の Dynamic Type に当たる）が効かなくなる。200% に拡大しても、はみ出しや重なりが出ないようにする。
- **太さは 400・600・700 の3種類だけ。** HIG では Light 以下の細いウェイトを避けるよう勧めている。
- **強調はサイズ・太さ・色の順で考える。** 書体を増やしたり、下線や斜体に頼ったりしない。
- **1行は 40 文字以内を目安にする**（PC では本文の最大幅を `max-width: 40em` 程度に）。

## 3. 色

配色は M3 のカラーロール（役割ごとの色の名前）で管理する。具体的な色の値は、カラーパレット案を決めたあとに `src/app/globals.css` へ定義する。

- **コンポーネントに色コード（#xxxxxx）を直接書かない。** 必ずロール名のトークンを使う（例：`bg-primary` `text-on-surface`）。
- **文字色は「on-」の付いた対のロールを使う。** primary の上の文字は on-primary、primary-container の上は on-primary-container。この組み合わせなら、コントラスト比 4.5:1 以上が保証される。
- **面の重なりは、影ではなく色で表す。** 下から順に surface → surface-container-low → surface-container → surface-container-high → surface-container-highest。
- **ダークモードに対応する。** `prefers-color-scheme: dark` で、ダーク用の値に切り替える。
- **error は、エラーと取り消せない操作にだけ使う。** 装飾には使わない。
- **差し色は意味で使い分ける。** 旧トップの黄色と緑を差し色にする。
  - 黄色：注意を引いて、行動を促す案内（CTA、「ここでこうしてください」）に使う。まだ定義していないので、使うときに M3 のカスタムカラーとして `highlight-container: #FDCF49`／`on-highlight-container: #4B3900`（ダーク：`#584400`／`#FFE08F`。コントラスト比 7.5／7.3）を足す。
  - 緑：成功・完了の知らせに使う（tertiary）。
  - 飾りや区別のためだけには使わない。使うときは、先にモックで確認する。

| ロール | 使う場所 |
|---|---|
| primary / on-primary | 主ボタン、選択中の状態、リンク |
| primary-container / on-primary-container | 強調したいカード（「次の一手」など） |
| secondary-container / on-secondary-container | 2番目のボタン、選択チップ |
| tertiary-container / on-tertiary-container | 差し色の緑。**成功・完了の知らせ**（「作成しました」など）。それ以外には使わない |
| inverse-surface / inverse-on-surface / inverse-primary | 吹き出し（会員登録の案内など） |
| surface / on-surface / on-surface-variant | 背景、本文、補足文 |
| outline / outline-variant | 入力欄・枠線ボタンの線 / 区切り線 |
| error / on-error / error-container | エラー表示、削除ボタン |

## 4. ボタン

### 種類と使い分け

HIG のボタンスタイル（Filled / Tinted / Bordered / Plain）を、M3 のロールに対応させる。

| 種類 | 見た目 | 使う場面 | 1画面あたり |
|---|---|---|---|
| 塗り | primary の塗り、on-primary の文字 | その画面でいちばんしてほしい操作 | **1つまで** |
| トーン | secondary-container の塗り | 2番目の操作（「あとで」「スキップ」など） | 制限なし |
| 枠線 | outline の線、primary の文字 | 補助的な操作 | 制限なし |
| テキスト | 背景なし、primary の文字 | 「詳細」「戻る」などの軽い操作 | 制限なし |
| 削除系 | error の文字か線 | 削除・取り消しなど、元に戻せない操作 | — |

- 削除系の操作を、画面の主ボタン（塗り）にしない。塗りの削除ボタンは、確認ダイアログの中でだけ使う。

### サイズと配置

- **タップできる範囲は 44×44px 以上**（HIG の最小値）。見た目が小さいアイコンボタンも、余白を足してこの大きさを確保する。
- ボタンとボタンの間は 8px 以上あける。
- スマホでは、主ボタンを画面の下側（親指が届く位置）に置き、横幅いっぱいにしてもよい。
- 横に2つ並べるときは、主操作を右、キャンセルを左にする（HIG のアラートと同じ並び）。

### ラベル

- 押すと何が起きるか分かる言葉にする（「提案を見る」「記録する」）。
- 「OK」「はい」「いいえ」「送信」だけのラベルは使わない。
- 短くまとめる。長くても全角10文字程度。

### 状態

- 通常・押下・キーボードでのフォーカス・処理中の4つの見た目を、すべての種類で用意する。
- **処理中はボタンの中にインジケーターを出し、続けて押せないようにする**（`aria-busy="true"`）。二重送信を防ぐため。
- 無効状態（disabled）はなるべく使わない。押せない理由が伝わらないため。使う場合は、理由をボタンの近くに書く。
- ページを移動するものは `<a>`（Next.js の `Link`）、その場で何かを実行するものは `<button>` にする。

## 5. モーダル

### 使ってよい場面

HIG では、モーダルは「作業の流れを止めてでも必要なとき」に限っている。

- 取り消せない操作の確認（削除など）
- その場で終わる短い作業（絞り込み、1項目の入力など）

上の2つに当てはまらないもの（長いフォーム、読み物、何段階もある操作）は、ページにする。

### 種類

| 種類 | 用途 | 決まりごと |
|---|---|---|
| 確認ダイアログ（HIG：Alert） | 取り消せない操作の確認、重大なエラー | タイトル1行＋説明は2文以内。ボタンは2つまで（キャンセル＋実行）。実行ボタンには「削除する」のような具体的な言葉を使う |
| シート（HIG：Sheet） | 短い作業 | スマホでは下から出し、PC では中央に出す。タイトルと閉じるボタンを必ず置く |

### 守ること

- **閉じ方を必ず用意する。** 「閉じる」か「キャンセル」のボタン、Esc キー、背景のタップのどれでも閉じられるようにする。
- **入力の途中で閉じようとしたら、破棄してよいか確認する。** 入力した内容が黙って消えないようにするため。
- **モーダルの上に、別のモーダルを開かない。**
- **ネイティブの `<dialog>` を `showModal()` で開く。** フォーカスがモーダルの外に出ない仕組み、Esc で閉じる動作、背景を操作できなくする動作が、ブラウザに最初から用意されている。自作しない。
- 開いたら、タイトルか最初の操作要素にフォーカスを移す。閉じたら、モーダルを開いたボタンにフォーカスを戻す。
- `aria-labelledby` で、タイトルとダイアログを結び付ける。
- 開いている間は、背景がスクロールしないようにする。

## 6. アクセシビリティ・使いやすさ

| 項目 | 基準 |
|---|---|
| コントラスト | 本文は 4.5:1 以上。大きな文字（24px 以上、または 19px 以上の太字）と UI 部品は 3:1 以上（WCAG 2.2 AA） |
| フォーカス | キーボードで操作したとき、`:focus-visible` で常にフォーカスリングを見せる |
| 代替テキスト | 画像には `alt` を付ける。アイコンだけのボタンには `aria-label` を付ける |
| フォーム | ラベルは常に表示する（プレースホルダーだけにしない）。エラーは項目のすぐ下に、直し方まで書く |
| 動き | `prefers-reduced-motion` が有効な環境では、アニメーションを止めるか最小限にする |
| 待ち時間 | 1秒を超えそうな処理には、インジケーターを出す。数秒以上かかるものは、目安の時間か進み具合を出す |
| 余白 | 4 の倍数で取る（4・8・12・16・24・32px）。M3 の 4dp グリッドに合わせるため |
| 画面端 | iPhone の画面の角や下部のバーに要素が隠れないよう、`env(safe-area-inset-*)` の分だけ余白を足す |
| 自動テスト | `src/app/a11y.test.tsx`（axe）に新しいページを追加する |
